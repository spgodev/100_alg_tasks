# Задача: In-memory кэш с TTL

## Контекст

У нас есть медленный источник данных — например, поход по сети в соседний сервис за карточкой товара (~200 мс на запрос). Нужно написать кэширующую обёртку, чтобы не ходить туда на каждый запрос.

Кэш будет использоваться конкурентно из множества горутин.

## Этап 1. Базовый кэш с TTL

Реализуйте кэш со следующим интерфейсом:

```go
// Loader — функция загрузки значения из медленного источника.
type Loader func(ctx context.Context, key string) (string, error)

type Cache interface {
    Get(ctx context.Context, key string) (string, error)
}

// NewCache создаёт кэш поверх loader.
// ttl — время жизни записи после загрузки.
func NewCache(loader Loader, ttl time.Duration) Cache
```
Требования:

- Если значение по ключу есть в кэше и не протухло — вернуть его из кэша, не вызывая loader.
- Если значения нет или его TTL истёк — вызвать loader, сохранить результат в кэш и вернуть его.
- Кэш должен корректно работать при конкурентном доступе из многих горутин.

## Этап 2. Защита от дублирующихся загрузок

Представьте: ключ протух, и в этот момент приходит 1000 одновременных запросов `Get` на этот ключ.

Доработайте кэш так, чтобы при конкурентных промахах по одному и тому же ключу loader вызывался **ровно один раз**, а остальные горутины дожидались результата этой загрузки и получали его.

При этом промахи по *разным* ключам не должны блокировать друг друга.

Стандартную библиотеку использовать можно, внешние пакеты (включая `golang.org/x/...`) — нельзя.
